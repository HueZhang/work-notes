

ESB 迁移踩坑：同一台服务器，老项目能跑，新项目报 BadImageFormatException

现象：
把 ESB 调用代码迁到另一个老 MVC 项目，本地调试正常，部署到服务器 IIS 报错：
未能加载文件或程序集“EsbInterop”或它的某一个依赖项。试图加载格式不正确的程序。

迷惑点：
ESB 老项目和这个迁移项目，在同一台服务器上。老项目访问正常，新项目死活报错。

排查：
1. 看服务器 bin，EsbInterop.dll 在。
2. ILSpy 看缺个 framework 的 dll，补上引用发布，还是报错。
3. 查 BadImageFormatException，发现是 32 位 / 64 位不匹配。

为什么老项目行，新项目不行：
- EsbInterop.dll 是 32 位（x86）编译的。
- 老项目部署时，可能早就单独配了应用程序池，并且把“启用 32 位应用程序”设成了 True。
- 新项目发布时用了默认的应用程序池，IIS 默认跑 64 位，64 位进程加载 32 位 DLL 直接抛异常。

解决办法：
IIS → 应用程序池 → 找到新项目对应的池 → 右键高级设置 → 启用 32 位应用程序 → 改为 True → 回收程序池 → 刷新。

备忘：
- 报“未能加载文件或程序集... 试图加载格式不正确的程序”，先查 IIS 应用程序池的 32 位设置，别折腾 web.config 和依赖。
- 如果服务器上还有纯 64 位项目，最好给这个 32 位的单独建一个应用程序池，别混用。
